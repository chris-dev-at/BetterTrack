# Origin demo evaluation tour

This is the fastest way to evaluate whether the sixth BetterTrack direction feels like
one connected wealth suite rather than several products sharing a sidebar.

Everything is fictional and local. Consequential actions either update the connected
demo state, enter Review with an exact diff, or state clearly that they stop at a
simulation boundary.

## 1. Start from nothing

1. Open the account menu at the lower-left.
2. Choose **Authentication**, then **Create an account**.
3. Run the complete Origin first-run:
   account identity, goals, data home, passkey, tax residence, first portfolio,
   structure, source, collaboration, review rhythm, and activation.
4. Activate the generated workspace and reload once.

Look for: one coherent mental model, explicit data ownership, and a useful portfolio
after activation rather than an empty generic dashboard.

## 2. Inspect portfolio truth

1. Press `Ctrl/Command + K` and open **Personal wealth**.
2. Inspect the large 208-point performance chart and change periods.
3. Open Holdings, Activity, Cash flow, Analysis, Plan, Automate, Files, People, and Tax.
4. Use the Structure and Settings controls in the portfolio header.

Look for: the chart belongs to the page instead of floating as a dashboard tile;
expenses, documents, tax, access, policies, and plans remain attached to the portfolio.

## 3. Change the ledger

1. Open Assets and search for Microsoft.
2. Open MSFT, choose **Add to portfolio**, build an order, review it, and simulate the
   fill.
3. Return to Personal wealth and inspect Activity, Holdings, cash, and the receipt.
4. Use Create for income, an expense, or a zero-net internal transfer.

Look for: one change propagates across the same portfolio model and survives reload.

## 4. Import and reconcile

1. Use command search for **Import and reconcile portfolio data**.
2. Choose a source, map fields, inspect duplicates and missing basis, reconcile totals,
   then apply atomically.
3. Open Review for the unresolved assumption.
4. Inspect the import receipt and undo boundary.

Look for: imports do not bypass evidence, reconciliation, tax, or human review.

## 5. Work with possibilities

1. Open Workbench Studio.
2. Change the asset, monthly amount, and duration; inspect the recalculated detailed
   projection.
3. Send the exact scenario to Review.
4. Open Rebalance, calculate the constraint-aware plan, inspect quantities, cash, tax,
   turnover, protected holdings, and the frozen checksum.
5. Select All wealth and open Rebalance to see why an aggregate must choose one
   authoritative portfolio first.

Look for: Workbench branches from truth but cannot silently write back to it.

## 6. Operate the portfolio

1. Personal wealth → Activity → **Portfolio events**.
2. Confirm the safe MSFT dividend and inspect the receipt.
3. Return to Activity and cash to see the connected ledger change.
4. Open Structure, propose an ownership or reparenting change, approve it in Review, and
   inspect the updated graph.
5. Open Portfolio Settings, save a harmless reporting-timezone change directly, then
   stage a calculation-policy change and approve it in Review.

Look for: safe deterministic writes can happen directly; material changes carry
lineage, consent, and an attributable decision.

## 7. Test private markets

1. Personal wealth → Cash flow → **Private markets**, or use command search.
2. Inspect committed, contributed, distributed, NAV, unfunded, IRR, TVPI, DPI, FX,
   valuation freshness, and source evidence.
3. Create a new commitment and reload.
4. Prepare Horizon Growth III’s capital call and send it to Review.
5. Approve it, then reopen Private markets and Cash flow.

Look for: the capital call changes the same live cash truth used by the rest of the
portfolio; approval updates paid-in/unfunded state and clears the pending proposal.

## 8. Trace data and evidence

1. Open Data Health from the Portfolio pulse.
2. Inspect a field, its authoritative source, lineage, and policy.
3. Request evidence, record an exception with a reason, or stage a correction in Review.
4. Open Files and link, annotate, version, archive, and restore evidence.
5. Open Control center → Backups for checkpoints, restore previews, exports, and
   retention.

Look for: “data quality” means inspectable fields and provenance, not a decorative score.

## 9. Collaborate without social clutter

1. Open People and inspect Together, Clients, Teams, Shared with me, and Updates.
2. Invite a collaborator or create scoped portfolio access.
3. Open Mia’s Riverside proposal in the shared Review queue.
4. Create a controlled share and inspect its permission/expiry receipt.

Look for: collaboration surrounds portfolio data; it does not become a disconnected
chat or engagement feed.

## 10. Inspect the platform boundary

1. Open Control center → Connections.
2. Run the simulated Google Drive, Parqet, broker, or bank lifecycle through
   permissions, OAuth, mapping, direction, staging, conflicts, logs, pause, and
   disconnect.
3. Open Developer and create an API key, OAuth app, webhook, or scoped MCP setup.
4. Inspect one-time secrets, scopes, test deliveries, request logs, and revocation.
5. Open Security for passkeys, TOTP, sessions, AI provider boundaries, data home,
   export, and deletion.

Look for: external systems connect to portfolio truth through explicit scopes, Review,
and receipts instead of becoming separate mini-products.

## Mobile check

Repeat steps 2, 5, 6, and 7 at a 412px viewport. Origin keeps the same capabilities,
adapts full-screen workspaces into mobile composition, preserves focus containment, and
does not introduce horizontal page overflow.

## Deliberate prototype boundaries

- No broker, bank, email, Drive, tax filing, or public attestation is real.
- AI creates grounded explanations and proposals but never silently writes.
- Human risk-willingness/capacity alignment, persistent advisor service cycles, and
  independently attested proof-of-wealth remain later production work.
- A production build should code-split the large demo bundle; this prototype favors a
  single inspectable frontend over delivery optimization.
